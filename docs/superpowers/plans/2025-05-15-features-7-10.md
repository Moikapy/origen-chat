## Feature 8: D1 Session Sync (Authenticated Users Only)
**Files:** New `app/api/sessions/route.ts`, `lib/session-sync.ts`, migration, `lib/use-sessions.ts`
**Effort:** Medium

### Phase 8a: D1 Migration + API Routes
- [ ] Create migration `0003_sessions_sync.sql` with `sessions` table (id, user_id, title, model, system_prompt, messages JSON, created_at, updated_at)
- [ ] Create `app/api/sessions/route.ts` with GET (list user sessions) and POST (upsert session)
- [ ] Both routes require auth — return 401 for unauthenticated
- [ ] Scope all queries with `WHERE user_id = ?` (ADR-001)
- [ ] Test: curl unauthenticated → 401, curl authenticated → scoped results

### Phase 8b: Client Sync Logic
- [ ] Create `lib/session-sync.ts` with:
  - `pushSession(session)` — POST to `/api/sessions` 
  - `pullSessions()` — GET from `/api/sessions`
  - `syncIfNeeded()` — push local if `updatedAt > serverUpdated`, pull server if newer
- [ ] In `use-sessions.ts`, add sync on mount (if authenticated) and on session change
- [ ] Debounce sync — don't write to D1 on every keystroke during streaming
- [ ] Test: verify session-sync.ts pushes/pulls correctly with mocked fetch

### Phase 8c: Auth Integration
- [ ] In `useAuth()` hook, expose loading state and user ID
- [ ] Guard sync: only sync if `user` is not null
- [ ] On login: pull sessions from D1 and merge with local
- [ ] On logout: keep local sessions, stop syncing
